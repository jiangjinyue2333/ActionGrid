# ActionGrid 0.4.8 验证记录

2026-10-22，版本 `0.4.8` / `24`。针对用户提供的 7748 桌面版本，修复返回桌面后图标操作丢失，以及单个应用双击空位时错误丢弃托起信息的问题。

## 复现与修复

用户提供的 `actiongrid-diagnostics(3).log` 只有管理应用记录，没有桌面原生动作、数据库或空位诊断。以下结论来自实际生产 C++ 的本地复现，不把该日志当作真机根因证据。

1. **返回时生成的节点缺少操作。** 原生窗口恢复焦点的回调可能同步创建图标节点，此时模块仍记录桌面没有焦点。旧代码直接返回原始节点，读屏可能缓存整组操作都没有的图标。现在仍为这些真实节点补充操作；页面状态、虚拟空位和公告继续等待焦点恢复，避免后台播报或过早播报。
2. **托起信息被错误丢弃。** 托起时保存的是数据库 favorite ID，放下时却要求它等于无障碍节点 ID。这两种编号并不相同。现在按托起时记录的选择顺序复用对应的 favorite，保留 ID 和容器校验。回归从实际托起入口开始，让图标名称随数据库快照更新，再双击真实空位；7748 的 op 855 仍收到原图标 ID 和正确目标坐标。
3. **读取失败误报为没有空位。** 原先所有移动请求构建失败都提示“没有可拖放的位置”。现在分别提示托起信息失效、目标位置变化、目标页读取失败或容量不足；失败继续保留托起状态，便于取消或重新选择。

代码改动位于 `app/src/main/cpp/native_init.cpp`，行为回归位于 `app/src/test/cpp/native_grid_test.cpp`。没有修改原生偏移、7748 操作号或放置成功确认条件。

## 验证边界

本轮在已有 Android 17 模拟器中执行实际生产 C++，仅替换系统 ABI、数据库快照和 dispatcher 边界。没有连接用户的 7748 手机，也没有重做真实读屏端到端验收。已验证复现中的操作注入、图标身份保留、移动请求及错误提示，尚不能声称覆盖真机上所有导致这两个现象的原因。

真机复核重点：多次进入应用再返回桌面，确认“系统桌面”播报后图标操作持续存在；托起单个应用、双击空位，确认放下后图标可触摸和浏览，重启桌面后位置仍保留。
