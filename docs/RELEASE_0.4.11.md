# ActionGrid 0.4.11 验证记录

2026-10-22，版本 `0.4.11` / `27`。

## 翻页提示与页码指示器

自动翻页公告使用“第 X 页共 Y 项”，替换桌面的“第 X 页共 Y 页”。页码指示器的节点描述恢复系统默认值，不再改写；主动聚焦页码指示器时仍由桌面提供原本的页码提示。项目数继续按当前页桌面项目统计：文件夹算一项，底栏和文件夹内部项目不计入。

重复公告的原因是事件 ABI 读取错误：窗口字段实际位于 `0xc4`，旧代码读取 `0x90`，导致桌面公告被误认为来自其他窗口；Rust 字符串也需要按容量、指针、长度读取，不能把预留容量当成文本长度。修复后延迟到达的原生页码公告会参与已有去重。其他窗口和非页码公告不受影响，项目数或公告发送尚未就绪时仍保留原生反馈。

窗口偏移依据本地 7748 系统库中 `AccessibilityRecord::set_source` 的指令：`0x84ff88` 写入 `[x0, #0xc4]`，`0x84ff94` 写入 `[x0, #0x90]` 的是另一字段。原生回归直接使用这些实际偏移，并构造容量大于长度的公告，避免测试和实现共用错误常量而漏检。

## 托起来源与成功反馈

用户提供的 `actiongrid-diagnostics(5).log` 来自 0.4.10、Android 17、桌面 7748。日志反复记录“旅行交通”的 `lift source placement unresolved`、`move source unresolved`，当时数据库快照已就绪。该节点是桌面文件夹，旧来源查询只匹配应用的 `itemType = 0`，无法匹配文件夹的 `itemType = 2`。

来源与占用目标现在按节点类型匹配，优先使用当前页；托起后保留已确认的 favorite ID，翻页或快照标签变化后继续使用同一来源。无法区分的同名文件夹仍拒绝移动，避免移动错误项目。此修复针对桌面上的文件夹，不改变文件夹内部项目的支持范围。

成功操作继续通过无障碍公告提供反馈，中文文案核对自本地 `com.miui.home-RELEASE-7.00.00.2259-04301440.APK` 的资源与 `DragController` 调用：

| 操作 | 系统桌面原文 | 资源依据 |
| --- | --- | --- |
| 单项托起 | `已拖起` | `announce_for_drag` + 空的 `drag_single_item_name` |
| 多选托起 | `已拖起2个图标` | `announce_for_drag` + `drag_multiple_item_name`，按实际数量替换 |
| 放置成功 | `已放置在第3页，第1行，第2列` | `announce_to_drop_workspace`，按实际目标位置替换 |

澎湃 4 使用现有可靠公告通道发送这些原文，保留控制器恢复后的补发；没有仅以点击事件代替语音反馈。Java 托起路径同步使用相同文案，已有桌面原生放置流程继续提供成功反馈。放置成功仍须确认最终数据库位置与目标页图标节点，未确认时保留对应失败提示。

## 验证

- 正式构建执行 `gradlew.bat clean test lint assembleRelease`，另执行 `assembleDebug`，均成功。118 项 Java 测试通过，无失败或跳过。
- Lint 0 错误、6 项警告（app 4 项，hook 2 项）。
- 项目结构、原生能力策略及 APK ABI 正反样例检查通过。
- 正式签名 APK 的包名、版本、API、Xposed 元数据、DEX 入口、arm64 ABI 与固定发布证书校验通过。
- `git diff --check` 通过。

证据保存在忽略目录 `artifacts/page-drag-0.4.11/`：`native-red.log`、`native-event-red.log`、`native-feedback-red.log`、最终 `native-green.log`、系统库 ABI 派生文件与说明、`launcher7-resources.txt` 及 `DragController.java`。原始系统库的可加载内容未改动；派生文件仅修复用于反汇编的符号节元数据。

本轮未连接用户的 7748 真机，未完成真实桌面拖动及 TalkBack/解说端到端验收；模拟边界回归不等同于真机验收。
