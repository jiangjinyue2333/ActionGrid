# ActionGrid 0.4.10 验证记录

2026-10-22，版本 `0.4.10` / `26`。

## 真机日志结论

用户提供的 `actiongrid-diagnostics(4).log` 来自 0.4.9、Android 17、澎湃 4 桌面 7748。原生记录能够进入导出文件，确认这台手机的日志传输通道已接通。

三次放下均收到虚拟空位点击并发出批量移动，数据库确认通过，但约 4.5 秒后都记录 `model move committed visible=0 focused=1`（原生序号 143、185、236）。因此不能把问题归结为没有收到点击。旧日志未记录源 favorite、目标坐标、刷新后的实际数据库位置和候选节点，尚不能确定真机失效的全部原因。

## 放置确认与诊断

- 在原生移动调用前注册目标节点观察，避免调用返回前产生的图标节点被遗漏。
- 桌面重载并清除托起网格后，立即发送内容变化事件，再等待节点确认。旧顺序在等待超时后才通知读屏，依赖该通知重新查询节点的读屏会被误报为未刷新。
- 目标图标必须处于目标页。整树查询优先使用同一棵树的原始页码标签，避免同名、同坐标的其他页面图标被当成成功。
- 确认窗口结束后再次读取数据库位置。如果刷新后位置已变化或无法读取，不再播报“位置已保存”或“已放置”。
- 新日志记录 `move source`、`move target`、`move visibility target`、`move db stage=initial/committed/timeout/after_reload`、`move candidate` 和 `move visibility result`。可分别检查源图标与 favorite ID、目标页/格子/屏幕坐标、原生操作号及字节数、数据库前后位置、候选节点名称/页码/边界以及未匹配原因。
- 每次放置最多记录 12 条候选节点，结果保留观察总数、同名节点命中数和最后同名节点的页码/边界，避免读屏重复查询挤掉日志。新增数据库复查继续运行在移动工作线程。

## 澎湃 4 翻页提示

页码节点与原生翻页播报统一为“第 X 页共 Y 项”。Y 复用已有数据库快照中的本页桌面项目数：文件夹按一个桌面项目计，底栏与文件夹内部项目不计，空页为 0 项。

原始页码标签先供内部导航、网格与总页数识别使用，之后才更改交给读屏的节点描述。返回桌面时提前构造的节点也会改写。翻页公告按桌面窗口和页码文案识别，不再只接受一个固定来源节点编号；其他窗口和非页码公告不处理。原有公告去重、取消翻页及数量未就绪时保留原生反馈的行为继续有效。

## 验证

复用在线的 `emulator-5556`（Android 17 / x86_64），未启动或新建模拟器。

`./scripts/test-native-grid.ps1 -Serial emulator-5556` 在修改前已复现以下失败：

1. 页码节点仍朗读总页数。
2. 实际桌面节点发出的页码公告绕过项目数播报。
3. 其他页的同名图标被误认为放置成功。
4. 先等待、后通知导致已成功移动仍被报为未确认刷新。
5. 原生接口返回前产生的节点没有进入确认流程。

修改后 53 项原生回归全部通过，另覆盖刷新改写位置后的失败反馈、实际移动到诊断导出的完整证据，以及候选节点日志限量。测试调用生产 `performNativePlacement`、节点/事件 Hook 和日志缓冲，仅替换系统 ABI 边界。

- `gradlew.bat clean test lint assembleDebug assembleRelease --console=plain` 成功；118 项 Java 测试全部通过，Lint 0 错误、4 项既有警告。
- 项目结构、原生能力策略及 APK ABI 正反样例检查通过。
- 正式签名 APK 的包名、版本、API、Xposed 元数据、DEX 入口、arm64 ABI 与固定发布证书校验通过。
- `git diff --check` 通过。

验证日志位于忽略目录 `artifacts/drag-page-20261022/`。这证明模块内部的确认与播报流程通过模拟边界测试；尚未完成用户 7748 真机的实际拖动、桌面模型刷新与真实读屏端到端验收。
